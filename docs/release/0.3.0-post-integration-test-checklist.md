## 0. Candidate binding (do first, record in the packet)

```bash
git -C <candidate-worktree> rev-parse HEAD
git -C <candidate-worktree> status --porcelain=v1
git -C <candidate-worktree> diff --stat <merge-base>..HEAD
```

Record: candidate SHA, branch, merge base, tracked/untracked inventory and a
diff fingerprint. A gate result without a SHA is not evidence.

## 1. Python gates (authoritative mirror of CI)

GitHub Actions is rate-limited for this account; `.github/workflows/ci.yml`
points at `scripts/local-ci.sh` as the authoritative local mirror. Run it
inside the candidate worktree, under the shared heavy-gate lock.

```bash
flock -n /tmp/stewardship-heavy-gates.lock \
  scripts/local-ci.sh --json                # python gates
flock -n /tmp/stewardship-heavy-gates.lock \
  scripts/local-ci.sh --with-node --json    # + dashboard/desktop JS gates
```

What it runs, and what must be reported for each: lockfile check
(`uv lock --check`), install-extras import check, full suite with
`--cov-fail-under=87`, `ruff check src`, `ty check` on the four trust-boundary
files, `pip-audit`, `compileall src tests`, and the api-extra import
(`from hermes_project_stewardship.api.server import create_app`). With `--with-node`:
dashboard `tsc --noEmit`, dashboard `npm test`, dashboard build, `npm audit
--omit=dev`, and the Desktop harness
`DOCKYARD_CAPTURE_SCREENSHOTS=0 node --experimental-vm-modules --test repro-live.test.mjs`.

Report per gate: exact command, exit code, pass/fail/skip counts, and the raw
log path emitted by the script (it writes every gate log under a per-run
evidence directory). The script exports a disposable `HERMES_HOME` /
`HERMES_KANBAN_HOME` — keep that isolation for any manual reruns.

Equivalent direct commands (if the script cannot be used):

```bash
uv sync --locked --extra dev --extra plugin
uv run --locked --extra dev --extra plugin pytest --cov=hermes_project_stewardship \
  --cov-report=term --cov-fail-under=87
uv run --locked --extra dev --extra plugin ruff check src
uv run --locked --extra dev --extra plugin ty check \
  src/hermes_project_stewardship/security/allowlist.py \
  src/hermes_project_stewardship/api/middleware.py \
  src/hermes_project_stewardship/plugin.py \
  src/hermes_project_stewardship/persistence/store.py
uv run --locked --extra dev --extra plugin pip-audit
uv run --locked --extra dev --extra plugin python -m compileall src tests
```

`hermes verify --json` also exists and reads `.hermes/environment.json`, but its
pipeline ends by starting the app in the background and polling readiness.
Prefer `scripts/local-ci.sh` for gate evidence, and only run `hermes verify` in
a disposable environment where a background start is acceptable.
